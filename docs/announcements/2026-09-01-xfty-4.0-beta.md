# XFTY 4.0 is in beta

*2026-09-01*

XFTY 4.0 is feature-complete and open for testing on the
[`4.0-beta`](https://github.com/nilvon9wo/ExtremeApexTestDataFactory/tree/4.0-beta)
branch, and as the
[`v4.0.0-beta.1`](https://github.com/nilvon9wo/ExtremeApexTestDataFactory/releases)
pre-release.

## What changed, in one sentence

3.5 let a test describe *a record*. 4.0 lets a test describe *a graph* — parents,
children, shared ancestors, and values that depend on each other — and still
insert none of it if you don't want to.

## The headline features

- **Context-aware values.** A field whose value is derived from another record in
  the graph — a sibling, an ancestor several hops up, or (under deferred insert)
  a child. `Contact.Department` copied from its Account's `Site`; a billing
  country that always matches the shipping country a validation rule pairs it
  with.
- **Shared ancestors.** Fifty Contacts under *one* generated Account, with one
  `insert`. Deep record-type hierarchies where every chain converges on the same
  root. Flat vs. deep is auto-detected.
- **Downward generation.** `with(...)` generates the records *below* a primary —
  an Account with its Contacts, each with their Cases — nested as far as you
  need.
- **Per-call relationship control.** Force one optional relationship, or skip one
  that would otherwise generate, for a single call — without touching the
  Provider.
- **Deferred and depth-batched insert.** Build a large graph across several
  helper methods and insert it once; or collapse a `NOW` call to one `insert`
  per dependency level instead of one per object type.
- **Governor-limit warnings.** Generation that quietly eats half your CPU or DML
  budget now says so in the debug log before the test fails.

The full list — including every breaking change — is in
[CHANGELOG.md](../../CHANGELOG.md).

## Breaking changes

4.0 batches every breaking change into one release, on purpose. Most are
mechanical renames. If you use the bundled Providers and nothing else, the
migration is small: re-vendor the source, pass a lookup to the constructor,
rename any value-expression types you reference. If you wrote your own Providers,
there's a bit more — a changed `createBundle` signature, a keyed Provider lookup
— all spelled out with exact before/after in the
[migration guide](../reference/migration.md).

## What "verified" means here

- **100% line coverage**, measured on a real scratch org (the framework ships as
  `@IsTest`, so Salesforce reports 0% until you strip the annotation to measure).
  Every test passes; no class carries an uncovered line.
- **Every documentation example is a runnable test.** A CI job extracts every
  `apex` code block from the docs and fails the build if it isn't backed, line
  for line, by a test that runs. Copy an example from the docs and it works.
- **Load-tested.** The `XFTY_Load` suite pins where generation breaks each
  governor limit, so the numbers in the docs are measured, not guessed.

## How to try it

- **Just testing:** download the `v4.0.0-beta.1` pre-release, or check out the
  `4.0-beta` branch, and point your tests at it exactly as you would the shipped
  version.
- Start with [docs/use/getting-started.md](../use/getting-started.md); the
  [roadmap](../roadmap/README.md) is the honest status of every feature,
  including the handful of documented limits.

## Feedback wanted

Start a thread in
[Discussions](https://github.com/nilvon9wo/ExtremeApexTestDataFactory/discussions)
(or [open an issue](https://github.com/nilvon9wo/ExtremeApexTestDataFactory/issues)
if you hit an actual bug). Most useful:

- Does the migration guide match what you actually hit?
- Which of the new features earns its place, and which feels like ceremony?
- **The open question:** XFTY ships as `@IsTest`-only today. Making it deployable
  as ordinary Apex would also let it seed sandboxes and scratch orgs — but then
  it counts toward your org's Apex limits and needs its own test coverage. Worth
  it? See [docs/roadmap/open-questions.md](../roadmap/open-questions.md).

APIs may still change before 4.0 final. That's what a beta is for.
