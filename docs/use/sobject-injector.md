# `XFTY_SObjectInjector` — write what `put(...)` rejects

`XFTY_SObjectInjector` is the JSON `serialize`/`deserialize` round-trip that
[`inject` / `injectAll`](enrichment.md) run internally, exposed as a standalone
utility. Reach for it when you have a plain `List<SObject>` — generated by XFTY or
not — and the code under test needs something an in-memory SObject can't hold:

- a **populated parent relationship** (`contact.Account`, `task.Who`);
- a **child subquery** (`account.Contacts`);
- a **read-only / formula / roll-up-summary / system** field
  (`contact.LastActivityDate`, `record.CreatedDate`);
- a **compound** field (`contact.MailingAddress`).

It takes no bundle and does no DML. Collect the grafts fluently, then `result()`
does **one** `JSON.serialize` and **one** `JSON.deserialize` over the whole list,
regardless of how many rows or grafts. The inputs are never mutated; the return
is a `List<SObject>` of new instances.

▶ Runnable: `XFTY_Ex_SObjectInjectorTest`

---

## The shape

```apex
List<Contact> enriched = (List<Contact>) XFTY_SObjectInjector.inject(contacts)
    .relationship('Account', accounts)                                  // one Account per contact
    .value(Contact.CreatedDate, Datetime.newInstance(2024, 1, 1, 9, 0, 0))
    .result();

enriched[0].Account.Name;      // readable off the SObject - was a null-pointer
enriched[0].CreatedDate;       // the forced system field
```

Every graft **aligns 1:1** with the records you passed to `inject(...)`. A
mismatch throws a clear `XFTY_DummySObjectFtyProviderException` naming the graft.

---

## Parent relationships — `.relationship(name, parents)`

`name` is the **relationship name**, not a field token — `'Account'` for
`Contact.AccountId`, `'Parent'` for `Account.ParentId`, `'Foo__r'` for a custom
lookup. (`inject` / `injectAll` resolve the name from the field for you;
`XFTY_SObjectInjector` does not.)

```apex
List<Contact> enriched = (List<Contact>) XFTY_SObjectInjector.inject(contacts)
    .relationship('Account', accountsAligned1to1)
    .result();
```

- `parents` must be the **same length** as the records.
- A `null` entry leaves that row's relationship `null`.

### Polymorphic

`WhoId` / `WhatId` resolve to `'Who'` / `'What'`. The parent keeps its concrete
type through the round-trip:

```apex
List<Task> enriched = (List<Task>) XFTY_SObjectInjector.inject(tasks)
    .relationship('Who', new List<SObject>{ new Contact(LastName = 'Lead') })
    .result();
enriched[0].Who;                       // a Contact
((Contact) enriched[0].Who).LastName;  // 'Lead'
```

## Child subqueries — `.childRelationship(name, childrenPerRow)`

`childrenPerRow` is a `List<List<SObject>>` — **one inner list per record**, in
the same order.

```apex
List<List<SObject>> contactsPerAccount = new List<List<SObject>>{
    new List<SObject>{ new Contact(LastName = 'A'), new Contact(LastName = 'B') },  // account 0
    new List<SObject>{ new Contact(LastName = 'C') }                               // account 1
};

List<Account> enriched = (List<Account>) XFTY_SObjectInjector.inject(accounts)
    .childRelationship('Contacts', contactsPerAccount)
    .result();

enriched[0].Contacts.size();          // 2
enriched[1].Contacts[0].LastName;     // 'C'
```

An empty inner list gives an **empty** subquery (`.size() == 0`), not `null`.

### Nested subqueries

A child record that already carries its own subquery keeps it — build the inner
level first, graft the result as the outer level:

```apex
List<Contact> contactsWithCases = (List<Contact>) XFTY_SObjectInjector.inject(
        new List<SObject>{ new Contact(LastName = 'Owner') })
    .childRelationship('Cases', new List<List<SObject>>{ new List<SObject>{ new Case(Subject = 'x') } })
    .result();

List<Account> enriched = (List<Account>) XFTY_SObjectInjector.inject(accounts)
    .childRelationship('Contacts', new List<List<SObject>>{ contactsWithCases })
    .result();

enriched[0].Contacts[0].Cases[0].Subject;   // 'x'
```

## Forced values — `.value(field, v)` and `.valuePerRow(field, values)`

`.value` sets the same value on every row; `.valuePerRow` takes one value per row
(same length as the records).

```apex
List<Account> enriched = (List<Account>) XFTY_SObjectInjector.inject(accounts)
    .value(Account.CreatedById, UserInfo.getUserId())       // same on every row
    .valuePerRow(Account.AnnualRevenue, new List<Object>{ 100, 250 })
    .result();
```

### Compound fields

Pass a `Map` of the compound's **lowercase components** — `city`, `street`,
`state`, `postalCode`, `country`, `latitude`, `longitude`, … Setting the
components as separate fields does **not** compose the compound.

```apex
List<Contact> enriched = (List<Contact>) XFTY_SObjectInjector.inject(contacts)
    .value(Contact.MailingAddress, new Map<String, Object>{ 'city' => 'Portland', 'street' => '2 Oak St' })
    .result();

Address a = (Address) enriched[0].MailingAddress;
a.getCity();     // 'Portland'
a.getStreet();   // '2 Oak St'
```

### `Blob` fields

A `Blob` can't pass through the JSON, so the injector **carries it across** —
captured off the record, kept out of the round-trip, re-applied to the result. So
both a forced Blob and a pre-set one survive:

```apex
List<Attachment> enriched = (List<Attachment>) XFTY_SObjectInjector.inject(
        new List<SObject>{ new Attachment(Name = 'f.txt') })
    .value(Attachment.Body, Blob.valueOf('file contents'))
    .value(Attachment.CreatedDate, Datetime.newInstance(2024, 1, 1, 0, 0, 0))
    .result();

enriched[0].Body.toString();   // 'file contents'
```

A `Blob` on an injected **parent / child** record (not a top-level record) is
dropped.

## Limits

- **`MOCK`-only in spirit.** A value or relationship you force in is fiction a
  real `insert` overwrites — see
  [unit-vs-integration](advanced/unit-vs-integration.md) point 4.
- **DML at your own risk — not enforced.** Nothing blocks `insert` / `update` on
  an enriched record, but a mocked `Id`, populated relationship objects and
  read-only / formula values make it throw (`INVALID_FIELD_FOR_INSERT_UPDATE`,
  *field is not writeable*, `MALFORMED_ID`) or, worse, pass silently on a shape
  the database could never produce.
- **Snapshot / independent copies.** An injected subquery or parent is a fixed
  copy; code that mutates it and re-queries won't see the change, and the two
  ends of a grafted relationship are not the same instance.
- **Cost.** One `serialize` + `deserialize` per `result()` call — cheap for a
  wide-but-shallow shape, heavier as payload size grows. Nested levels are
  separate `result()` calls.
